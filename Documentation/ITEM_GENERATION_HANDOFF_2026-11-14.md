## What exists now

- **Roller:** `Code/Data/ItemGeneration/ItemRoller.cs` handles every item: dungeon end, travel, new-game armor,
  trade-ups, the Item Generation lab, MCP tools and sims. Entry points are on `LootGenerator`
  (`GenerateLoot`, `GenerateTradeUp`, `GenerateNewGameBonusLoot`, `Roll(request, out spec)`).
- **Knobs:** `lootSystem.itemGeneration` (`ItemGenerationConfig`), patchable. The active patch (night-v45i) doesn't
  set it, so the code defaults apply.
- **Data:**
  - `GameData/ItemMods.json` (188 families) is generated by `Scripts/build-item-mods.py`. Re-running the script
    **overwrites** hand edits, so edit the ladders in the script.
  - `RarityTable.json` holds rarity weight, `MinLevel`, `Pools`, `MaxLines` and `Explode`.
  - `Weapons.json` / `Armor.json` gained class, damage/defense ranges and an implicit `triggerName`.
- **Sheets:** ITEM MODS and RARITY tabs, and named class / damage / defense columns on WEAPONS and ARMOR.
  - In your local `SheetsPushConfig.json`, the weapons, armor, prefix and suffix tabs are pushed only if you set them
    to true (most are false now).
  - Pulling the new tabs needs `itemModsSheetUrl` and `raritySheetUrl` in `SheetsConfig.json`.
- **Stats:**
  - `DF.exe ITEMSTATS --dump out.json --levels 1-100 --count 100 --seed 1` writes every roll decision per item.
  - `python -I Scripts/item-stats.py out.json stats.json` aggregates a dump.
  - `ITEMSTATS --samples N` prints full items.
  - The dashboard "Item Roller 10k" (https://claude.ai/artifact/GENbD9BiivU5zghhsCtTVk) shows the latest seed-1 roll
    from one attached file. To refresh it, upload a new `item-stats.json` and repoint the 17 sources' `source.url`.
    Its Anomalies section lists items that tripped a rule in `find_anomalies` (item-stats.py), each tag with its reason.

## What a 10k roll shows (seed 1, after a88c8e33)

- **Rarity:** about 85% Common, 12% Uncommon, 2% Rare. Flat across item levels.
- **Lines:** 2.4 per item, almost all stat lines and actions. Material is about 0.1 per item and mechanic about 0.06.
- **Animal suffixes:** about 0.03 per item, spread over 114 animals, so animal sets are nearly unreachable.
- **Common-only "Lucky" tiers:** about 22% of Common stat lines. That may be too frequent.
- **Material lines:** about half come from pool roll-ups (stat → material), not from rarity minimums.
- **Material share differences** (e.g. Willow on top) are seed noise: across 3 seeds the leader changed every time.

## Done after the handoff (2026-11-15)

- **Implicits scale with item level** (`ItemImplicitScaling`): percent mechanics (next-action / this-swing damage,
  amp, speed) × (1 + `ImplicitPercentPerItemLevel` 0.01 × (ilvl − 1)); flat ones (heal, armor, weapon damage) by
  `ImplicitFlatPerItemLevel` 0.02. Discrete values (thresholds, faces, multihit, +1 attribute, statuses, strip moves)
  and `scaleFrom` implicits stay as cataloged. The scaled value is saved on the bundle and written into its
  description; `ITEMSTATS --dump` records `implicitValue`. Both knobs are balance-pass placeholders.
- **Naming:** `[Lucky] [prefix] [Material] Base [suffix]` ("Lucky Wicked Iron Cuirass of the Ox"). A common-only
  line's "Lucky" moves to the front once. Rule / listener families keep one keyword for every tier (tooltip shows the
  tier). Bases renamed so none contains a material word: Crystal Stiletto → Faceted Stiletto, Shadow Dagger → Umbral
  Dagger, Silver Stiletto → Moonlit Stiletto, Crystal (wand) → Lodestone, Mithril Chestplate → Knight's Chestplate;
  typos Curiass → Cuirass, Chopoper → Chopper, lowercase legs bases capitalized. `ItemArt/index.json` renamed to
  match. Old saved items keep their old names (and may lose their icon).
- **Wood and Cloth drop:** class-less Common-rank material rows (PRIMARY 2, the low rung, like Stone) in
  `PrefixMaterialQuality.json`. They already had a set build, a synthesis store (KINDLING / FRAY) and convert actions
  (KINDLE / UNRAVEL); Cloth got two more piece triggers (Moth, Silkworm) to reach 6.
- **Rarity by level:** user call: rarity stays static the whole game. Epic / Legendary / Mythic `MinLevel` (5 / 15 /
  15) set to 1, so every rarity can drop at any item level with the same weights.

## Open work, roughly in order

1. **Balance pass.** Every gear number moved and night-v45i was measured on the old loot. Placeholder values to tune:
   rarity `Pools` / `MaxLines` / `Explode`, roll-up chances, `DamagePerItemLevel` 0.01, `AttributePerItemLevel` 0.02,
   tier ladder multipliers and weights in the script, and the Lucky tier weight (¼ of the tier below it).
   Use the `/balance` workflow (scan → focus → confirm). The user prefers implementing before testing; run sims only
   when they ask.
2. **Thin pools:** decide whether material and mechanic lines should be more common (rarity minimums, `ExtraPoolWeights`
   3:1:1:1), and whether 120 single-tier animal families need grouping or more weight.
3. **Rarity by level:** nothing makes later dungeons drop better rarities. A design call.
4. **Implicits don't scale with item level** yet. Bases with no implicit include all starter bases.
5. **Naming pass:** rule and listener families use "Greater / Grand <name>", common-only tiers use "Lucky <keyword>".
   Base names that contain a material word read oddly ("Steel Shadow Dagger").
6. **Wood and Cloth** have set definitions but no material prefix rows, so they never drop. A design call.
7. **Tag-restricted action slot** ("+1 slot, Bone actions only") is a plain +1 slot today. A real one would be a new
   mechanic; the user wants to minimize new mechanics.
8. **Merge plan:** `item-gen-redesign` → `v44-enemies-environments` → `main`, once the balance pass is accepted.
   Ask before pushing.

## Gotchas

- The shared checkout has other sessions editing it. Don't `git stash`; use a worktree for baselines (see memory).
- `DF.exe` is often running from `Code/bin/_agent_build` (the MCP server). `Code/bin/Debug` builds are fine.
- Stat suffix values are **percent of a reference stat** that already grows with hero level, not flat numbers.
- Mod lines live on the existing `StatBonus` / `Modification` objects with a `ModLine` tag. An item whose `BaseName` is
  set gets its name from `ItemGenerator.ComposeRolledItemName`.
- An item's implicit trigger survives save load only because `MaterialTriggerMerge` keeps bundles matching
  `Item.Implicit`. Keep that in mind if trigger clean-up changes.
