# DungeonFighter-v2 — Codebase Reference

## Project Overview

- **Type:** .NET 8.0 desktop game using Avalonia UI (v11.2.7)
- **Assembly:** `DF` (entry point: `RPGGame.Program`)
- **Namespace:** `RPGGame`
- **Project file:** `Code/Code.csproj`
- **Key dependencies:** Avalonia 11.2.7, ModelContextProtocol 0.5.0-preview.1, SoundFlow (audio), NLayer (MP3), Google.Apis.Sheets.v4

## Core Architecture

### Entity Hierarchy

```
Actor (abstract)               — action pool, all status effects
  └── Character : Actor        — player character (composition-based)
        └── Enemy : Character  — enemy entities
```

**`Actor`** (`Code/Entity/Actor.cs`) — base for every combat participant.
- `ActionPool` — list of `(Action, probability)` tuples; `SelectAction()` does weighted random pick
- Status effects stored directly: poison/burn/bleed (DoT), stun, weaken, roll penalty, damage reduction, harden, fortify, focus, expose, HP regen, pierce, reflect, silence, stat drain, absorb, temp HP, confusion, mark
- Tempo statuses (2026-11-16, `Code/Combat/TempoStatuses.cs`, stores `brittle` / `stagger` / `haste` / `rattle`): Brittle (next crit taken +25%/stack), Stagger (holder's next action +15% longer/stack), Haste (own actions 10% faster/stack, −1 per own action), Rattle (= roll penalty); Mark now really forces the next landed hit to crit. Knobs `combat.status*` (cap 4, Expose/Focus/Harden 0.20 per stack)
- Expose (`ExposeStatus`) absorbed Vulnerability and Armor Break (2026-11-11): stacks to `StatusMaxStacks` remove Defense; applications at the cap strip armor (tier 2). `vulnerability` / `armorbreak` effect ids still load as Expose
- `Stores` (`Code/Combat/Stores.cs`) — one read / add / spend interface over material mints (RAGE, GRAZE…), statuses and hero resources; `TriggerEvents` (`Code/Combat/Events/TriggerEvents.cs`) — the single trigger event vocabulary (canonical WHEN tokens, aliases, labels, slot families)
- DoT tick methods: `ProcessPoison`, `ProcessBurn`, `ProcessBleedOnAction`
- `UpdateTempEffects(actionLength)` — decay all timed effects each turn

**`Character`** (`Code/Entity/Character.cs`) — player character via composition:
| Component | Class | Responsibility |
|---|---|---|
| Stats | `CharacterStats` | STR/AGI/TEC/INT, class points, temp bonuses |
| Effects | `CharacterEffects` | combo state, shields, rerolls, slow, misc buffs |
| Equipment | `CharacterEquipment` | slot references (Head/Body/Legs/Feet/Weapon) |
| Progression | `CharacterProgression` | level, XP, thresholds |
| Actions | `CharacterActions` | action pool and combo sequence |
| Health | `CharacterHealthManager` | current/max HP, armor, damage, heal |
| Combat | `CharacterCombatCalculator` | damage/speed calculations |
| Facade | `CharacterFacade` | unified public API, delegates to all above |
| Equipment Mgr | `EquipmentManager` | equip/unequip logic |
| Level Up Mgr | `LevelUpManager` | level up/down logic |
| Session Stats | `SessionStatistics` | per-run tracking (kills, damage, etc.) |

Core stats: `Strength`, `Agility`, `Technique`, `Intelligence`  
Class points: `BarbarianPoints`, `WarriorPoints`, `RoguePoints`, `WizardPoints`  
Combo system: `ComboStep`, `ComboSequence`, `IncrementComboStep(lastAction)` with routing via `ComboRouter`  
Save/load: `Character.SaveCharacter()` / `Character.LoadCharacterAsync()` → delegates to `CharacterFacade` → `CharacterSaveService` → JSON in `GameData/`

### Items (`Code/Items/`)

- `Item.cs` — base item with slots, rarity, mods, bonuses
- Item generation: `Data/ItemGeneration/ItemRoller.cs` rolls every item (item level → slot/class → tier → base → rarity → material → lines → name); entry points on `LootGenerator`; knobs `lootSystem.itemGeneration`; design `Documentation/ITEM_GENERATION_REDESIGN_2026-11-14.md`
- Base modifiers (2026-11-15): every base, starters included, has one fixed modifier in its catalog row (`modifier` = CrossWires rule(s) with `{lo-hi}` values, no name since 2026-11-17, written by `Scripts/build-item-mods.py`); only the values roll (`BaseModifierRoller.FromCatalog` → `Item.ImplicitRule`). Since 2026-11-17 (`Documentation/BASE_MODIFIERS_2026-11-17.md`; regenerate with `build-item-mods.py --modifiers-only`) a base modifier changes or enhances another system and never grants a % stat bonus (POTENCY is the one percent): tier 1 = one action or the class (APPLY a status, MINT a store, TAGAS, a DoT, POTENCY), 2 = a tag or a status chain (APPLY / ADD, `ONSTATUSAPPLY:x -> APPLY y`, class TAGAS), 3 = skill tree / set / store (`RANK node n`, `SETCOUNT n`, tag MINT, `ONCASH:store -> APPLY`), 4 = bends a rule (EXEMPT COMBO|STREAK, COUNTAS event aliases, ONSTOREFULL, tag → tag TAGAS, crit APPLY), 5 = a pair whose halves feed each other. Modifier verbs (passive only): `TAGAS tag` (the swing counts as that tag for rule conditions, PER TAGS, strip adjacency, cadence ifTag / perTag and class-tag counts; `CrossWires.HasTag`), `RANK node_id n` (effective rank on a learned node: rule scaling and router effects, not prerequisites; `CrossWires.EffectiveSkillRank`, `SkillRanks`), `SETCOUNT n` (the piece counts n more toward its material set). `GameData/BaseModifiers.json` keeps the class tag lists and the fallback pools for saves. Materials add no trigger to the piece; legacy implicit triggers migrate on load (`ItemSaveMigration.MigrateLegacyImplicit`), and a saved modifier whose rule shape no longer matches its base's catalog rule re-rolls (`ItemSaveMigration.RefreshCatalogModifier`). Items carry no trigger bundles since 2026-11-18: the item-trigger path (`EquippedItemTriggerApplicator`, `ItemEquipEffectApplicator`, `Triggers.json`, the material trigger catalog, the trigger scenario runner and Action Lab panel) was deleted; old saves' `triggerBundles` / `equipEffects` are ignored on load
- Roll rules (2026-11-15, design doc §14): weapon damage is the base's own tier-scaled range (no item-level multiplier) and swing time drops `weaponSpeedPerTier` per tier; rarity roll-up is 2% per step, unlimited, and a rolled-up item's lines roll at its drop rarity (`Item.DropRarity`); Commons have 1-2 lines and suffixes come out of the line count; every mod family tier has its own name
- `InventoryManager.cs` — add/remove/sort inventory
- `InventoryOperations.cs` — equip/unequip business logic
- `ComboManager.cs` — combo action management for items
- `ItemPrefixHelper.cs` — rarity/tier name generation
- `AttributeRequirement.cs` — stat thresholds for equipping

Item mods are defined in `GameData/ModificationTables.json`.

### Actions

Actions loaded from `GameData/ActionTables.json` via `ActionLoader`.  
`Action` has: Name, Type (`ActionType`: Attack, Spell, Support, etc.), Tags (string list), ComboOrder, length, damage/effect values.  
Tags drive behavior via `GameDataTagHelper`, `TagDamageCalculator`, `ActionMechanicTagProcessor`, `ActionRollTagProcessor`.  
Environment/hazard actions from `GameData/EnvironmentalActions.json`.  
Cadence timing (2026-11-15, `Code/Data/CadenceTiming.cs`, `Documentation/CADENCE_TIMING_2026-11-15.md`): TURN ×N = the next N rolls (hit or miss); ACTION ×N = one copy on each of the next N strip slots (per-slot queue, redeemed when that slot lands a combo, clipped at the strip end; ×1 uses the next-action bank). A bundle's optional `timing` object (cadenceBundlesJson and the bonus group) adds `slot` (1..n / first / last), `delay` (ACTION skips slots, TURN waits rolls), `shape` ramp / decay / charge (charge = the old all-on-one-action burst), `every` n (TURN), `perSlot` (× this action's slot), `slotIf` (3, >=3, first, last, odd, even), `untilMiss` (TURN), `ifTag` (TURN: waits for, and only counts down on, an action with the tag) and `perTag` (× strip actions with the tag). An action's bundles share one duration (the first bundle's). The `RELEASE n` verb (UNLEASH, CODA) pulls every queued TURN grant and other-slot grant onto its swing at +n%. Item/skill rules read `SLOT` (1-based strip slot) and `SLOTS` (strip length). 18 actions use it (GATHERING STORM … NEXT TIME).  
Gear action rolls (2026-11-12, `GearActionPools`, `Documentation/ACTION_CLASS_SORT_2026-11-12.md`): every rollable action is tagged to one class (`class, <class>`), one hybrid (`hybrid, <name>, <classA>, <classB>`) or neither (20 neutral). Since the 2026-11-14 item redesign only weapons lean in-class: a weapon's action comes from its own class's actions `lootSystem.itemGeneration.weaponActionClassShare` (0.7) of the time; other slots draw from the whole rollable pool; starters, `unique` rows and material set converts never roll.  
Verb presets (2026-11-11, `Code/Combat/Verbs/`; trimmed 2026-11-19 per D6.4 / D6.6): an action's `verb` column reads/spends `Stores`. The generic verbs are CASH IN (`CASH FULLEST 75`, spends your fullest material store, `FullestStore`; `ATTUNED` in older data reads the same, attunement is gone) and DETONATE (`DETONATE 100`, the target's largest status); store-named cashes (`CASH stagger 100`), `RELEASE n` and `APPLY status n` (runs as the card's rule `ONCONNECT -> APPLY|ADD`, `ActionRules.FromVerb`) remain. LIQUIDATE, RECKONING, INDEX, MARK, BARRIER, DISTILL, TRANSMUTE, INVEST and PALM are retired: their rows are deleted and saved names load as CASH IN (BARRIER → BULWARK, DISTILL → DETONATE) via `ActionLoader` aliases. The synergy bot scores verbs with `verbWeights` in `synergy-bot.json` (`RulesSynergy.VerbSynergy`, gear-gated: CASH IN needs a formed set, a status cash an owned applier). It also prices affix templates (`affixWeights`, `RulesSynergy.AffixValue`: worth their weight only on a planned set / a minted cross-wire source) and adds skill-pick bonuses for usable cross-wire nodes and Persistence capstones. CASH takes an optional payout (2026-11-18, `CashPayout`): `CASH FULLEST 100 INTO <DAMAGE|HEAL|STR|AGI|TEC|INT|PRIMARY|store id>`; damage is the default, hero resources (temphp, harden, fortify, focus, haste) land on the hero, statuses on the target, per-unit rates `CashPayout.DefaultRates` (patch: `combat.cashIntoPerUnit`); 10 cash-in actions use it (RESTORE, SURGE, BULWARK, GRIT TEETH, CENTER, BLOODLET, QUICKEN, IGNITE, LAY BARE, STEEL NERVE). PRELUDE / BLOOD OATH are data PREPs; the `cost` column (`HP 5`, `ActionCost`) pays HP on resolve.

Build system hooks (2026-11-11, `Documentation/BUILD_SYSTEM_CONDENSED.md`):
- One rule engine (2026-11-18, `Code/Combat/Rules/`, design D6.11–D6.16): `RuleBook.For(hero)` is the hero's cached rule list in owner order (worn items Weapon→Feet, then material sets' earn rules in MaterialBuilds.json order (`CrossWireRule.SetBuild`, 2-piece gate checked on fire; not in `CrossWires.Active`), then skill nodes in tree order, never learn order; rebuilt when items, ranks or trees change) and every rule reader goes through it; `RuleEngine` dispatches triggered rules gains-first (MINT/ADD/APPLY), the item that granted the swing's card first, then owner and written order; events raised while another resolves queue FIFO (`RuleEngine.Raise` / `Scope`, one scope per combat event in `TryMintFromEvent`), up to 2 generations (deeper ones dropped, counted in `ChainsStopped`, logged); `RuleEngine.Trace` records owner + generation per fire. Affix templates are item rules (`AffixTemplates.Rules`: TUNE = MINTBONUS material, STORECOND = `IF KEYWORD>=n` DAMAGE, COUNTSDOUBLE = SETCOUNT, OPENER = `IF SLOT=1`, FINISHER = `IF SLOTSLEFT=0`, BLOODPRICE = DAMAGE + coded HP cost, LISTEN = item-owned set mint); MINTBONUS applies to every mint (`MintKeyword`). Action trigger bundles (the data / sheet format) convert once per action to action-owned rules (`ActionRules`, `Code/Combat/Rules/ActionRules.cs`): they fire only on the card's own swing (card filters and event check via `ActionTriggerGate`), through `RuleEngine` (owner = the card, heroes and enemies), from `ActionRules.Dispatch` (SWING rules in the pre-damage pass); new verbs `SWING DAMAGE|SPEED|AMP n%` (this swing, card rules only), `STRIP op[:arg] [n]`, `RETRIGGER next|opener|finisher|slot:n`, `CRITFACE n`, flat `HEAL n HP`, self key `MISSINGHP`; owned mechanics skip the whole-row apply (`ActionTriggerOwnership`). ONROOMSCLEARED count 1 now means every clear. Verbs, conversions and enemy/room owners are still separate paths (next migration steps)
- `HeroEventHub` (`Code/Combat/Events/`) fires hub events ONSTATUSAPPLY, ONCASH, ONSTOREFULL, ONBEAT, ONSELFCOST, ONENEMYACT (not seen by action trigger bundles) to material WHENs, Listener affixes and cross-wires; all mints go through `MaterialSetController.MintKeyword`
- Item affix templates are prefix `Effect`s in `Modifications.json`: `LISTEN` (`ListenerAffix`, event rolled on drop from the slot family), `TUNE`, `STORECOND`, `COUNTSDOUBLE`, `OPENER`, `FINISHER`, `BLOODPRICE` (`AffixTemplates`, generated as item rules), `CROSSWIRE` (`crossWire` rule)
- `CrossWires` (`Code/Combat/CrossWires.cs`) is the item/skill rule language: `WHEN[:arg] [EVERY n] [IF cond [AND cond]] -> MINT|ADD|APPLY|HEAL|REFLECT|BUFF ...` and passive `WHILE [IF cond] -> DAMAGE|ARMOR|SPEED|HIT|COMBO|CRIT ±n[%] [PER TARGET status]`; skill families Alias (`ONMISS -> COUNTAS ONTAKEHIT`, one hop, combat events), Exemption (`WHILE [IF] -> EXEMPT STREAK|COMBO`) and Threshold (`ONSTOREFULL:<store> -> ...`), 12 class nodes (`-th-`/`-al-`/`-ex-`); conditions read hero stores, HP, combo step, amount spent, action length, roll, distinct materials, turn, target status/HP and enemy prefix tags. Sources: skill nodes (`crossWire`, 12 class nodes), CROSSWIRE prefixes (8) and RULE prefixes (25 unique-item effects: Vampiric, Thorned, Butcher's, Towering, Silvered, ...; `{n}` = rolled value, `;` separates rules). Passive rules feed DamageCalculator (via `AffixTemplates.OutgoingDamagePercent`), `GetEffectiveArmor`, `SpeedCalculator` and `CadenceScopedBuffApplicator` roll bonuses. Build audit: `Documentation/BUILD_AUDIT_2026-11-11.md`
- Synergy pass grammar (2026-11-16): gates `ONCE`, `CHANCE n%`; conditions `WEAPON mace`, `PREVTAG` / `NEXTTAG tag` (strip neighbour), self keys `STR AGI TEC INT HITSTREAK EXTRASLOTS`; `PER TARGET x | SELF key | STAT INT [div] | WORN tag | TAGS tag | QUALITY a|b` on any rule; passive `AMP`, `MULTIHIT`, `STR/AGI/TEC/INT` (attributes via `GetSkillAttributeBonus`); verb `NEXT stat n[%] [FOR k] [RAMP|DECAY] [IFTAG tag]` (TURN grant). Skill node rule amounts scale by rank × power. 132 of 204 skill nodes are rule nodes (`customEffectId: "rule"` or `crosswire`). Custom-node pass (2026-11-18): triggered `SPEND store n|all` (raises ONCASH) and `NEXTROLL n` (next natural roll = n; both ignore rank scaling), passive `DROP class|material n%` (armor-drop material share; `CrossWires.DropChances` → `LootContext`), `MINTBONUS class|material|KEYWORD n` (+n per mint; `CrossWires.MintBonus`), flat `ARMOR n` (no %; `CrossWires.ArmorFlat`), self keys `LASTROLL` / `EXTRAHITS`, `PER TAGS <class>` counts gear + strip + hybrid partners (`ClassTags.Count`), fight-counter store `loaded` and resource `salvage` in `Stores`. Markets, Cadence, Synthesis, Level 2 - Barbarian, Snake Eyes, Second Wind, Second Chance and Dagger Mastery are rules; Archmage, Flow State, Technical Debt, Spell Memory, Grand Equation and Living Alloy were cut (Confluence branch gone). `SkillEffectRouter` keeps only the hybrid trees, the conversion table pass and per-rank pack mods; class roots stay in `ClassTags`
- Skill trees (2026-11-16): every class branch is tier bands (same-tier skills are parallel, each needs any one from the nearest lower tier; `SkillTreePrerequisites.GetBandPredecessorOptions`; hybrids stay single-file); node `excludes` makes either-or picks (checked both ways), 8 per class incl. a three-way cross-class Rite pick (`ONCASH:<other class store> -> ...`)
- `Persistence`: skill node `persist` (`hero:streak,focus` / `target:expose,...`) carries stores into the next fight (4 Rite capstones)
- `ConversionTable` + `GameData/Conversions.json`: target status conversions (Venom Mace, Envenomed Edge, Hemorrhage, Kindle, Thermal Shock) as data rows owned by customEffectIds

### Balance / Tuning Tools

Workflow: `Documentation/BALANCE_PROCESS.md` and `/balance` (scan → focus → paired fresh-seed confirm → gate). Balance is judged on real dungeon clear rate (`realClearAnchors`) and fight length (`heroTurnsAnchors`), never single-fight win rate; the old win-rate tuning stack (AutomatedTuningEngine, BalanceValidator, Suggesters, TUNESIM/TUNEAPPLY/WRSOLVE, Balance Tuning Workbench) was removed 2026-11-04. Agents can run the pipeline over MCP: `get_balance_context`, `start_dungeon_sim` / `start_bo_solve` / `start_balance_scan` / `start_median_check`, `get_balance_job`.

In `Code/Game/` and `Scripts/`:
- `Tuning/Profiles/BuildLadderRunner.cs` — `BUILDLAB` headless mode: prices build stepping stones, skill nodes and triggers (`GameData/TuningProfiles/build-ladders.json`; see `Documentation/BALANCE_PROCESS.md`)
- `Tuning/DungeonSimRunner.cs` — `DUNGEONSIM` headless mode: real dungeons at a fixed level with HP carried between fights (start-level hero, retreat rule); shard with `Scripts/dungeon-sim.py` (intervals over shards; `--solve` is deprecated, use bo-solve). Default bot is the synergy bot (the calibration bot since fastbot-syn47): the fast rules bot (`PlaythroughRulesPolicy`, priorities in `GameData/TuningProfiles/rules-bot.json`, `--bot rules`) plus a set/skill synergy layer (`RulesSynergy.cs`, weights in `GameData/TuningProfiles/synergy-bot.json`: actions scored by the worn sets' WHEN triggers and learned nodes, skills by worn-set branch); `--bot smart` picks by simulation, ~40× slower. Bot refresh 2026-11-15: gear is scored for the wearing hero (`ItemValueModel.Score(item, hero)`: attribute lines by attribute fit, tiered prefixes by rolled tier, base modifiers by strip coverage, extra slots, in-class actions); unmined actions score `unminedBase` + grant features, worn action rules pull their actions in, and `RulesSynergy.TimingPosition` places cadence-timing actions; the starting bag rolls for the hero. Results: `GameData/TuningRuns/bot-refresh-2026-11-15/`. Tools print a `Provenance:` line (`RunProvenance`)
- `Scripts/balance-dashboard.py` — local page (http://localhost:8765, launch config `balance-dashboard`) to start dungeon-sim / bo-solve / balance-scan with Spark and local slot counts, build `Code/bin/BalanceTools`, watch logs, and see the Spark's load, build freshness and vLLM state; its "Balance layers" section shows every measured layer (curve, class parity/identity, materials, affixes, build diversity, fight dynamics, per-enemy scan findings) from the newest result files, plus Fun report / Material grid / Affix grid jobs to refresh them
- `Scripts/simpool.py` — shard runner behind `dungeon-sim.py` / `surrogate-data.py`: `--spark N` adds N slots on the DGX Spark over `ssh spark` (auto-republishes the linux-arm64 build when `Code/` changes, uploads the session's GameData). Seeded shards are bit-identical to local ones
- `Scripts/balance-loop.py` — the main balance tool: `measure` (fresh-seed clear / hero actions / class spread vs `balance-targets.json`), `solve --knob damage|health|class` (bo-solve per off band, paired confirm on other fresh seeds, keeps what beats noise, writes an overlay patch), `botcheck`, `export` (dashboard data); `Scripts/balance-chain.py` runs health → damage → class → damage
- `Scripts/bo-solve.py` — Bayesian band solve (`--level L --knob damage|health|class:<Class>`; one 5-level region band, solve at a band midpoint like L8/L13; fresh seeds per round). `Scripts/balancepatch.py` reads/writes patches for every script (overlays `"base"`, step `bands`); `Scripts/simstats.py` holds the shared interval model; `--spark auto` is the default everywhere
- `Scripts/balance-scan.py` — wide quick look (~8 min): median build grid + small DUNGEONSIM sample, per-enemy / pacing / variety findings; `--compare` an earlier scan JSON. `balance-check.ps1` is the gate before proposing a patch
- `Scripts/surrogate-data.py` + `Scripts/surrogate.py` — balance surrogate: LightGBM trained on DUNGEONSIM shards under randomized knobs; `predict` / `sweep` / `solve` / `check` answer knob what-ifs in ms (screening only, confirm with `dungeon-sim.py`; retrain per patch)
- `Tuning/Profiles/Fundamentals*.cs` — FUNDMATRIX / FIGHTLOG / SEQLAB / *VALUE single-fight sims (bare or typical-gear hero): diagnostics and action/skill pricing, not curve targets
- `Tuning/LegacyTuningWriteGuard.cs` — blocks automated writers (MCP `save_variable_changes`) from overwriting the active patch; `DF_ALLOW_LEGACY_TUNING_WRITES=1` overrides
- `BattleStatistics/BattleStatisticsCalculator.cs` / `BattleExecutor.cs` — aggregate battle stats (Settings quick sims)
- Google Sheets export via `Google.Apis.Sheets.v4`

## Key Patterns

**Config access:** `GameConfiguration.Instance.Character.PlayerBaseHealth` etc. — always use the singleton.

**Facade pattern:** `Character` delegates everything through `CharacterFacade`; never bypass it to reach sub-components directly.

**Composition over inheritance:** `Character` has `Stats`, `Effects`, `Equipment`, etc. as properties rather than deep inheritance.

**Data-driven:** Actions, mods, rarities, enemies, flavor text — all JSON in `GameData/`.

**Event system:** State transitions fire `StateChanged`; combat fires via `CombatEventBus`; character switches fire `CharacterSwitched`.

**Save files:** Named `character_{FirstName}_{LastName}_{Level}_{shortHash}_save.json` or `_dead.json`. Loaded async via `Character.LoadCharacterAsync()`.

## Build

```bash
cd Code

dotnet run            # Run
dotnet publish -r win-x64 --self-contained   # Single-file release
```

Output assembly: `DF.exe`. Avalonia/SkiaSharp native libs are self-extracted at startup (`IncludeNativeLibrariesForSelfExtract=true`).

## Tests

Tests live in their own project, `Code/Tests/Tests.csproj` (assembly `DF.Tests`), so they stay out of `DF.dll` and game builds. Building it builds the game and copies `DF.Tests.dll` next to `DF.exe`. The game's `--run-tests` / `--run-test-filter` / `--list-test-suites` flags, the Settings → Testing panel and the MCP test tools load it at runtime via `RPGGame.Utils.Testing.TestAssembly` (calls by type/method name, so a rename in `Tests/` needs the matching string updated). `Code.csproj` excludes `Tests/**`.

```bash
dotnet build Code/Tests/Tests.csproj
Code/bin/Debug/net8.0/DF.exe --run-tests      # or Scripts/run-tests.ps1 [filter]
```

Unit tests in `Code/Tests/Unit/`.
Key test files: `ActionExecutionComponentsTest`, `BattleNarrativeManagersTest`, `GameDataGeneratorTest`, `TierDistributionTest`, `ColoredTextBuilderTest`.
